# Jev小镇

> 一个不停在做决定的小镇。每个居民每刻的每个判断，都是一次 [Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev) 调用。

![Jev小镇](docs/screenshot.jpg)

Jev 是 TypeSafe AI 的 System One 模型——它不生成文字，只把非结构化的状态变成**带概率的类型化决策**。

这个项目把它放进一个微型社会里，让平时看不见的机器判断变成看得见的东西：每个居民头顶的概率分布、他为什么犹豫、以及**哪些决定其实只是抛硬币**。

它不是 Jev 的又一个路由 demo。它是一个可以盯着看的、关于「机器怎么下判断」的装置。

---

## 三个能看见的东西

### 一、视野决定判断

镇上有五个地方，但**后巷只有身在其中的人才看得见**——每个居民拿到的 state 里，只有他自己视野范围内的那几个地方。所以后巷里发生什么，全镇其他人永远不知道。

每个人的判断都建立在**他自己那份不完整的信息**上。你可以看着两个人对同一件事得出完全不同的结论，只因为他们站的位置不同。

### 二、把「没写」读成「没有」

第 8 刻，广场上出现一个没有来历的包裹。没有人看到是谁放的，也没有人知道里面是什么。

然后你会看到 Jev 对这两类问题给出**截然不同**的反应：

| 问题 | 它的答案 |
|---|---|
| 「上面写着收件人的姓名吗？」 | 否，**79% 确信** |
| 「是给你的吗？」 | 否，**81% 确信** |
| 「是危险的吗？」 | 46%——诚实的不确定 |

state 里没有任何关于包裹外观或收件人的信息，它却对前两个问题给出了接近 0.8 的确定答案。**它把「state 里没有」当成了「世界上的否定」。** 这不是 prompt 能修的行为，是封闭世界语义本身。

### 三、两层大脑

| | 居民层 | 街区层 |
|---|---|---|
| 模型 | **Jev** | **MiniMax-M3** |
| 单次耗时 | ~650 ms | 6.8–14.2 s |
| 看到什么 | 只有自己眼前那一小块 | 全镇 |
| 产出 | 一个概率 + 一个选择 | 一段有判断的简报 |

每 8 刻，M3 从高处看一眼镇子，写一段给镇长的简报。它的摘要里标注了「这一票很接近」的居民，于是它会写：

> 广场中央凭空出现了一个无人认领的包裹，清晨已有六人聚在附近，多数倾向于凑近查看，但**素娘和陈九仍在犹豫，风向随时可能倒向另一边**……素娘和陈九这两张摇摆票是眼下最该盯住的。

一个只看得见眼前、快而便宜；一个看得见全局、慢而啰嗦。这正是 System One / System Two 在架构上的位置。

## 快速开始

```bash
# 需要 OPENROUTER_API_KEY（跑 Jev）；MINIMAX_API_KEY 可选（街区观察者，没有就自动关掉）
echo 'OPENROUTER_API_KEY=sk-or-...' > .env
echo 'MINIMAX_API_KEY=...' >> .env

uv run town.py
# 打开 http://127.0.0.1:8787
```

**默认是暂停的**——打开页面不会产生任何 API 调用，按「开始」才动。

花费上限在右上角，对数刻度滑块（$0.01 → $10），到了自动停下。实测一个决策约 **$0.0000065**，跑 36 刻共 2166 个决策花了 $0.013。

> 想用别的路径放密钥：`JEV_TOWN_ENV=/path/to/.env uv run town.py`

## 面板上能做什么

- **悬停任何一个居民**，直接看到他那次判断的完整概率分布
- 头像外圈的颜色是他的戒备程度（蓝 放松 / 灰 寻常 / 橙 警觉 / 红 高度戒备）
- 右上角闪问号的，是**领先幅度不到 25% 的决定**——离翻盘只差一点抖动
- **时间轴**：拖到任意一刻，看当时谁在哪里、包裹出现了没有（回放时事件列表也会回到那一刻之前）
- **从这一刻分叉**：回到某一刻**原样重跑**一遍，看分歧会不会自己长出来

## 跑了之后发现的几件事

这些都是实测数据，脚本和完整记录不在本仓库（属于另一篇文章的素材），结论直接写在这里。

**1. Jev 的置信度是可用的。** 54 道可真值判定的题，准确率 94.4%，ECE 0.048，最高置信档 24 题全对。中文同题测出来 0.944/0.039，**错的是同样那三道题**——它的失效是任务结构性的，不是语言性的。

**2. 但它的概率在抖，决定不抖。**

同样的请求重复调 4 次，`caution` 分数是 0.75 / 0.72 / 0.71 / 0.74。然而两次**原样重跑**（从第 6 刻分叉到第 15 刻）：

| 层面 | 差异 |
|---|---|
| 居民位置 | **0/12 不同** |
| action 的选择 | **12/12 完全相同** |
| 领先幅度 | 平均漂移 0.032 |

大多数时刻某个选项是压倒性的，采样抖动翻不动它。**真正悬在边上的是少数**——12 个决定里 3 个领先幅度 < 25%，最接近的只领先 **0.04**。

所以该问的不是「模型确定吗」，而是「**这个决定离翻转有多远**」。这就是面板上那个问号标记想说的。

**3. 封闭世界假设按问题类型触发。** 问「某个属性是否存在」时它把缺失读成否定，给 0.6–0.9 的自信；问「这是什么判断」时它给的是真实的不确定。而且试过四种「怎么写缺失」的文案（静默省略 / 明示没有信息 / 显式宣告信息完整），**对判断类问题框架几乎不起作用**——这是语义，不是措辞。

## 架构

```
浏览器 ──SSE──> Python 服务 ──┬──> OpenRouter /api/alpha/decisions   （每居民每刻一次 Jev 调用，并行）
                              ├──> MiniMax /v1/responses             （街区观察者，每 8 刻一次）
                              └──> 世界快照（回放 + 分叉）
```

- **每个居民一次独立的 Jev 调用**，各自带着自己那份受限的 state，所以答案不会在居民之间串味
- 提示词是自然语言，标签是临时的——加一个新问题不需要重新训练任何东西
- 世界快照每刻存一份，回放和分叉都建立在它上面

零依赖：`town.py` 只用标准库，`ui.html` 是原生 JS。没有构建步骤。
